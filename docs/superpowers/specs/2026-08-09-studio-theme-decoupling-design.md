# Post Studio 独立视觉与主题解耦设计

## 背景

IMX Post Studio 当前内置了一份来自 `hugo-theme-imx` 的主题快照，并通过同步脚本、版本清单、提交校验和主题一致性测试维护关联。该模式让预览实现、主题版本与两个仓库的发布节奏相互牵连，也使“主题一致性”成为持续维护负担。

本设计将两个项目彻底拆分为独立产品。`hugo-theme-imx` 保持不变；Post Studio 接管当前可见的 IMX 风格，作为自身长期维护的品牌与视觉实现。

## 已确认决策

- 采用“独立接管现有视觉”方案。
- `hugo-theme-imx` 不因本项目进行任何修改。
- 保留 `IMX Post Studio` 名称、现有标志和当前 IMX 风格视觉。
- 删除代码、资源来源、版本、构建、测试和发布层面的主题耦合。
- Post Studio 不再承诺自动跟随或完整复刻 `hugo-theme-imx`。
- 本次迁移不是视觉重设计；现有可见行为应尽量保持不变。

## 架构边界

### hugo-theme-imx

- 独立开发、测试、发布和回滚。
- 不读取 Post Studio，不包含 Post Studio 专用模板、清单、脚本或通知流程。
- 本次工作不修改该仓库。

### imx-post-studio

- 独立拥有应用视觉、Dock、字体配置、Markdown 预览、目录和响应式逻辑。
- 构建和测试不读取本地或远程 `hugo-theme-imx` 仓库。
- 名称和标志作为 Studio 自身品牌资产维护。
- 后续视觉演进不要求与主题同步。

依赖方向在迁移后不存在：两个仓库可分别发布、回滚和演进。

## 组件迁移

### 删除的耦合层

- 主题快照目录及其来源清单。
- 主题同步命令和同步脚本。
- 主题版本、Tag、Commit 和文件哈希校验。
- 仅用于证明主题来源或主题一致性的测试和 CI 步骤。
- README、维护文档和代码注释中的主题同步说明与一致性承诺。

### Studio 自有视觉层

当前可见风格保留，但应整理为用途明确的 Studio 模块：

- 应用级颜色、字体和表面 Token。
- Dock 与导航样式。
- 文章预览布局。
- Markdown 正文排版。
- 代码、表格、引用、列表和媒体样式。
- 目录、深浅色与响应式状态。

迁移后不得以主题版本或主题目录作为模块边界。文件命名和注释应描述 Studio 自身职责，而不是“主题副本”“主题覆盖”或“主题一致性”。

### 字体与授权

- 字体由 Studio 独立托管和加载。
- 正文必须具有可验证的 400 与 700 字重。
- 需要斜体效果时必须采用明确的真实字形或合成策略，不能依赖偶然的系统字体行为。
- Inter、Noto Serif SC 等第三方字体的 OFL 文件和其他必要授权必须保留。
- 在删除原主题许可证或来源说明前必须完成授权审计；不能以解耦为由删除依法或许可证要求保留的内容。

## 预览数据流

预览继续完全在浏览器中完成：

1. 编辑器产生 Markdown 和文章元数据。
2. Markdown 解析器生成经过安全过滤的 HTML、目录与阅读统计。
3. 本地图片通过受控 Blob URL 注入。
4. Studio 自有预览文档组合标题、元数据、正文和目录。
5. Studio 自有样式在隔离 iframe 中渲染深浅色与设备尺寸。

该流程不请求主题仓库、不上传文章内容，也不需要 Hugo、Vercel Function 或其他后端渲染服务。

## 行为与错误处理

- 移除主题清单后，不再出现主题版本或哈希不匹配错误。
- 预览资源缺失应在 Studio 构建阶段失败，不能在浏览器中静默回退到远程主题资源。
- 字体加载失败时允许使用明确的本地回退栈，但功能测试必须验证主字体的 400/700 字重可加载。
- Markdown、图片和 ZIP 的现有安全边界保持不变。
- 不因解耦改变草稿格式、导入导出格式或本地存储结构。

## 测试策略

### 行为回归

- 编辑、草稿、ZIP、图片、封面和导出流程保持可用。
- Markdown 加粗、斜体、删除线、代码、引用、列表、表格和图片正确生成与显示。
- 目录展开、收起、跟随滚动和锚点跳转正常。
- 深浅色切换不改变当前阅读位置。

### 视觉与响应式回归

- 保留现有 Studio 视觉快照，并将测试语义从“主题一致性”改为“Studio 视觉回归”。
- 覆盖浅色与深色、桌面与移动端、目录存在与不存在、目录展开与收起。
- 覆盖关键宽度与特殊尺寸，保证没有横向溢出或弹窗裁切。
- 标题和正文左边界在同一状态下误差不超过 1px。
- 验证正文 400 与 700 字体实际加载，不能只检查计算样式中的 `font-weight` 值。

### 解耦约束

CI 必须验证：

- 构建和测试不访问 `hugo-theme-imx`。
- 不存在主题同步脚本、主题清单或主题版本校验。
- 不存在远程主题 CSS、JavaScript 或字体请求。
- 产品名、标志和 Studio 自身的 IMX 品牌命名不属于违规引用。
- 法律授权、第三方许可证和历史归属说明不纳入机械删除规则。

## 文档与发布

- README 将 Post Studio 描述为独立的本地优先 Markdown 写作工具。
- 删除主题同步、固定主题版本和自动跟随主题升级的说明。
- 保留产品名、标志和 IMX 风格介绍，但不宣称预览与某个主题版本完全相同。
- Vercel 和 GitHub Actions 仅围绕 Post Studio 自身构建、测试与部署。

## 不在本次范围内

- 修改 `hugo-theme-imx`。
- 更换产品名称或标志。
- 重新设计现有视觉风格。
- 引入服务器端草稿、账号或云端渲染。
- 改变文章包、Front Matter、草稿或媒体格式。

## 完成标准

迁移完成必须同时满足：

1. `hugo-theme-imx` 工作树没有本次改动。
2. Post Studio 不再包含或执行主题同步机制。
3. Post Studio 构建、测试和部署可在没有主题仓库的环境中独立完成。
4. 当前名称、标志和整体视觉得到保留。
5. 现有核心功能、预览状态和响应式行为通过回归验证。
6. 文档准确描述独立维护关系。
7. 必要的第三方授权文件仍然完整。
