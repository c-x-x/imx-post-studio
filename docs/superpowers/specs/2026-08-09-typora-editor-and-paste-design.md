# Typora 式即时排版与编辑器图片粘贴设计

## 背景

IMX Post Studio 当前使用 CodeMirror 编辑原始 Markdown。编辑器已有格式工具栏和通过
媒体面板插入图片的能力，但正文始终显示源码标记；视觉换行没有明确启用；剪贴板图片
只有在媒体面板获得焦点时才能导入，不能在写作光标位置直接粘贴。

本设计在保留 Markdown 为唯一数据源的前提下，增加 Typora 式即时排版模式、完整源代
码模式和编辑器内图片粘贴。这里的即时排版只用于写作反馈，不替代现有整屏 IMX 文章预
览。

## 已确认决策

- 默认使用“即时排版”模式。
- 即时排版采用 Typora 式交互：光标所在段落显示 Markdown 标记，离开后显示排版效果。
- 工具栏提供“源代码”模式按钮，用于查看和编辑完整原始 Markdown。
- 两种模式共享同一份 Markdown、同一选区和同一撤销历史。
- 编辑器根据可用宽度视觉折行；视觉折行不得向正文写入换行字符。
- 剪贴板图片可直接粘贴到写作光标位置，并自动进入当前文章媒体库。
- 即时排版是轻量写作效果，不复刻整屏 IMX 文章预览。
- 保留现有名称、视觉、草稿、媒体面板、导入导出和文章预览流程。

## 编辑器架构

### 单一 Markdown 文档

CodeMirror 继续持有唯一的编辑文档。即时排版不维护 HTML 副本，也不把富文本反向转换
为 Markdown。所有编辑、工具栏命令、自动保存、导出和预览继续读取现有字符串。

这保证模式切换不会规范化、重排或丢失用户源码，也避免两个编辑器之间的光标同步。

### 显示模式

编辑器具有两个互斥显示状态：

- `rich`：即时排版，作为默认状态。
- `source`：完整 Markdown 源码。

工具栏右侧显示模式按钮。即时排版时按钮文案为“源代码”，进入源码模式后提供返回“即
时排版”的操作。按钮使用 `aria-pressed` 暴露状态，并可通过键盘操作。

模式是 Studio 界面状态，不属于文章元数据，不进入草稿、ZIP 或 Front Matter。切换模
式不得改变文档内容、选区、滚动位置和撤销/重做历史。

### 即时排版装饰

新增 CodeMirror 视图扩展，根据增量 Markdown 语法树生成 Decoration，不进行每次按键
的完整 Markdown 到 HTML 转换。扩展负责：

- 隐藏非活动段落的标题、粗体、斜体、删除线、链接和行内代码标记。
- 为对应内容应用标题、强调、引用、列表、链接、行内代码和围栏代码视觉。
- 光标或选区与一个逻辑段落相交时，恢复该段落的全部源码标记，保证精确编辑。
- 输入法处于 composition 状态时不切换当前段落装饰，避免中文候选输入和光标跳动。
- 图片引用在非活动段落显示本地图片部件；活动段落和源码模式显示完整 Markdown 引用。
- 无法解析或不支持可视化的结构保持原始源码，不能删除或改写内容。

首版可视化范围包括标题、粗体、斜体、删除线、引用、无序和有序列表、链接、行内代
码、围栏代码、分隔线和本地正文图片。复杂表格和原始 HTML 保持源码形式；完整最终效
果继续由“预览文章”验证。

### 响应式视觉折行

编辑器启用 CodeMirror 的 line wrapping。内容区域保持现有阅读宽度上限，但在窄窗口
使用全部可用宽度。长段落根据视口和侧栏状态自动折到视觉行；窗口再次拉宽时恢复为更
少视觉行。

验收时直接比较缩放前后的文档字符串，保证没有新增真实换行。编辑器和页面均不得因长
文本产生横向滚动。

## 图片粘贴数据流

### 事件入口

CodeMirror 通过 DOM paste 处理器读取 `clipboardData.items` 和 `clipboardData.files`。
仅当剪贴板包含受支持图片时阻止默认粘贴；纯文本、Markdown 和其他普通内容继续走
CodeMirror 默认行为。

图片粘贴在 `rich` 和 `source` 两种模式下都可用。

### 事务流程

1. 记录当前 CodeMirror 选区，并将正文媒体入口标为忙碌。
2. 提取剪贴板中的全部图片文件。
3. 复用 `prepareBodyMediaBatch` 检查格式、25 MiB 上限、MIME 与真实文件内容。
4. 根据当前媒体集合分配安全且唯一的名称；剪贴板缺少可靠名称时使用扩展名匹配的
   `image` 基名，并沿用现有 `-2`、`-3` 去重规则。
5. 全批次验证成功后，一次性加入当前草稿媒体，并在记录的选区插入对应 Markdown。
6. 多张图片按剪贴板顺序插入，每个引用单独成段，避免与相邻正文粘连。
7. 解除忙碌状态，恢复编辑器焦点；即时排版模式随后显示图片部件。

处理期间复用现有 `intakeBusy` 约束锁定工作区，因此选区不会在异步读取时漂移，也不能
切换文章或触发导出。媒体批次和 Markdown 引用必须共同成功；任何文件失败时两者都不
修改。

### 共享媒体入口

媒体面板的文件选择、拖放、面板粘贴与编辑器直接粘贴继续共用同一套校验和命名逻辑。
编辑器只新增事件入口和插入位置，不复制图片安全规则。右侧媒体列表仍展示粘贴产生的图
片，用户可继续执行插入和删除。

### Blob URL 生命周期

即时排版图片部件使用现有 `ObjectUrlRegistry` 提供的本地 Blob URL。文章切换、图片删
除和组件卸载继续撤销对应 URL，不增加远程上传或外部请求。

## 错误与边界

- 不支持格式、伪造 MIME、损坏图片或超限图片沿用现有中文错误信息。
- 批量粘贴任意一张失败时整个批次失败，不留下媒体或 Markdown 半成品。
- 处理失败后保留原文、原选区和当前草稿身份，并把焦点返回编辑器。
- 普通文本粘贴、复制、剪切、撤销、重做和输入法行为保持原有 CodeMirror 语义。
- 即时排版解析失败时降级显示 Markdown 源码，不阻止继续写作或导出。
- 不支持远程图片下载；已有 HTTPS Markdown 图片仍只按现有预览边界处理。

## 测试策略

### 单元与组件测试

- 语法装饰覆盖各类标记，并验证活动段落恢复源码。
- `rich` 与 `source` 切换不改变 Markdown、选区和撤销历史。
- line wrapping 改变视觉布局但不改变文档字符串。
- composition 开始到结束期间装饰状态稳定。
- 普通文字 paste 不被拦截。
- 单张和多张图片按选区与剪贴板顺序插入。
- 缺失名称、重名、伪造 MIME、损坏内容、超限和批次部分失败均符合事务语义。
- 图片部件创建和释放 Blob URL，不访问网络。

### 浏览器回归

- Chromium、Firefox 和 WebKit 覆盖即时排版与源代码模式。
- 在桌面、中间宽度和移动宽度验证视觉折行、无横向溢出和正文字符串不变。
- 验证标题、强调、引用、列表、代码、链接和本地图片的写作效果。
- 验证光标进入段落显示标记，离开后恢复即时排版。
- 从系统剪贴板粘贴图片，确认媒体列表、光标位置、即时图片和 Markdown 源码一致。
- 粘贴后的文章可保存、导出并重新导入，图片引用仍有效。
- 保留现有完整预览、草稿、ZIP、安全、响应式和可访问性回归。

## 不在本次范围

- 完整富文本编辑器或 HTML 到 Markdown 双向转换。
- 表格的所见即所得单元格编辑。
- 原始 HTML 的可视化编辑。
- Typora 插件、主题或文件系统功能。
- 上传图片到服务器、图床或云端草稿。
- 改变 IMX 文章预览页面。

## 完成标准

1. 默认写作页面提供 Typora 式即时排版，活动段落可精确编辑 Markdown。
2. 源代码模式可查看和编辑完整 Markdown，模式切换不改变文章数据或历史。
3. 编辑器随窗口宽度视觉折行，底层正文不产生额外换行。
4. 两种模式均可直接粘贴图片，成功时媒体与引用同时写入，失败时均不写入。
5. 粘贴图片可在即时排版中显示，并继续通过保存、导出和重新导入流程。
6. 中文输入、键盘、撤销重做、现有工具栏和媒体面板没有回归。
7. 静态、单元、构建及三浏览器回归全部通过。
